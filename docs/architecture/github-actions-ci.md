# GitHub Actions CI — Current Design & Operations

> **Status:** live on `main` through the DevInside-managed `node@v3` workflow.
> **Last updated:** 2026-07-17.

## 1. Canonical workflow

The repository has one canonical workflow:
`.github/workflows/devinside-ci.yml`. It is generated by the same deterministic,
panel-driven CI management path used for client repositories and carries the
marker `# devinside-managed: node@v3`.

The former handwritten `.github/workflows/ci.yml` was retained only during the
dogfood migration window. It was removed after the managed verification and
SonarQube jobs both passed on the merge of provisioning PR #4.

The managed file must not be edited by hand. Changes belong in
`apps/api/src/modules/ci/workflow-templates.ts`; bump the template version so the
existing content-aware management flow opens a reviewable update PR.

## 2. Triggers and permissions

The workflow runs on:

- every pull request;
- pushes to `main`; and
- manual `workflow_dispatch`.

Global workflow permissions stay at `contents: read`. The correctness job uses
no secrets. The push-only Sonar job can read the two repository secrets injected
by the DevInside GitHub App:

- `SONAR_TOKEN` — a generated project-scoped analysis token, never the global
  SonarQube admin/provisioning token; and
- `SONAR_HOST_URL` — the public HTTPS SonarQube URL.

## 3. Verification job

The `verify` job runs on pull requests, `main` pushes, and manual dispatches:

1. `actions/checkout@v4`;
2. `actions/setup-node@v4` with Node 20 and npm caching;
3. `npm ci`;
4. `npm run prisma:generate`;
5. `npm run lint`;
6. `npm run typecheck`;
7. `npm test`; and
8. `npm run build`.

Each command is detected from the root `package.json`; the generator never
invents a script. Prisma generation must precede typecheck/build because this
repository intentionally has no Prisma postinstall hook.

Reproduce the contract locally:

```bash
npm ci
npm run prisma:generate
npm run lint
npm run typecheck
npm test
npm run build
```

## 4. Code-quality job

The separate `code_quality` job is gated by
`github.event_name == 'push'`. SonarQube Community Build analyzes only the main
branch, so pull requests and feature branches never overwrite the project view.

The job:

1. checks out complete Git history (`fetch-depth: 0`) for accurate SCM blame;
2. installs the Node workspace deterministically;
3. runs `npm run prisma:generate`;
4. runs the workspace-fanning `npm run test:coverage`, producing
   `apps/api/coverage/lcov.info`;
5. invokes SonarSource's scan action pinned to immutable v8.1.0 commit
   `7006c4492b2e0ee0f816d36501671557c97f5995`; and
6. passes the provisioned project key plus:
   - `sonar.qualitygate.wait=true`; and
   - `sonar.qualitygate.timeout=300`.

The scanner action is not allowed to use the old `@v4` line: versions 4 through
5.3.0 are affected by CVE-2025-58178. A scanner/auth/transport failure or red
Quality Gate fails `code_quality` without hiding the independent `verify` result.

## 5. Automated provisioning path

Repository activation is manager-gated and uses the existing product flow:

1. **Enable scan** calls `provisionRepositoryCodeQuality`.
2. The backend validates `SONAR_PUBLIC_URL`, the provider, tenant membership,
   repository access, and GitHub App permissions.
3. The operator-level Sonar token creates/reuses a tenant-safe project and mints
   a fresh project-scoped analysis token.
4. The GitHub App sealed-box encrypts and writes the two Actions secrets.
5. DevInsight encrypts the project token in Neon, saves the project mapping, and
   audit-logs the action.
6. `enableCi` renders the current managed workflow and opens/reuses the
   `devinside/ci-setup` pull request.
7. An explicit manager action merges the reviewed PR; DevInsight never silently
   writes a workflow directly to `main`.

Required GitHub App repository permissions are:

| Permission | Access | Purpose |
|---|---|---|
| Metadata | Read | mandatory baseline |
| Contents | Read & Write | inspect files and commit the managed workflow branch |
| Workflows | Write | write under `.github/workflows/` |
| Pull requests | Read & Write | open and merge the setup PR |
| Actions | Read | synchronize workflow runs |
| Secrets | Read & Write | inject the analysis token and public host URL |

## 7. Failure guide

| Failure | First check |
|---|---|
| `npm ci` | root lockfile matches every workspace `package.json` |
| Prisma generation | `apps/api/prisma/schema.prisma` and generated-client command |
| Typecheck/lint/test/build | reproduce the exact root command locally |
| Secret injection 403 | GitHub App has `Secrets: read & write` and installation was re-accepted |
| Sonar unreachable | `SONAR_HOST_URL` points to public HTTPS `/sonarqube` |
| Sonar unauthorized | project-scoped `SONAR_TOKEN` exists; retry **Enable scan** to rotate/reinject |
| Missing blame | checkout remains `fetch-depth: 0` |
| Missing coverage | `npm run test:coverage` produced `apps/api/coverage/lcov.info` |
| Quality Gate timeout | Sonar Compute Engine health and the explicit 300-second limit |
